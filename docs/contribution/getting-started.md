# Getting Started

## Purpose

This page explains the minimum onboarding path for any developer contributing to Astrea-EIP.

## Rules

- Read the architecture and contribution sections before starting work.
- Every change starts with an issue.
- Every pull request must be linked to one issue.
- Work must happen in the repository that owns the concern.

## Procedure

1. Read `Architecture Overview`, `Repository Boundaries`, and `Git Workflow`.
2. Identify the target repository.
3. Create or pick the issue that defines the work.
4. Create a branch using the branch naming standard.
5. Implement the change and update documentation if required.
6. Open a pull request with the required description and evidence.

## Minimum readiness checklist

Before opening a first pull request, a contributor must understand:

- repository boundaries
- branch naming rules
- Conventional Commit rules
- pull request expectations
- documentation update rules
- CI blocking conditions

## Validation checklist

A new contributor is ready when they can create:

- a correctly scoped issue
- a valid branch name
- a valid commit message
- a pull request that satisfies the handbook rules
